Community

The standard is open, and the standard is the community's. Here is how to take part.

The code

github.com/bylazora - the engine (AGPL), the parsers (Apache-2.0), the sample migration, and the evidence annex. Issues and pull requests welcome; the CI pipeline re-runs the byte-exact gate on every push.

The agents

The rule pack teaches your coding agents the invariants: the validator is the only authority that marks a run proven, money is integer cents, and a MISMATCH is a diff to fix, never a threshold to tune. One canonical file, with notes on wiring it into Claude Code, Cursor, Copilot and the rest, rather than a copy per tool that drifts.

The conversations

Discussions on GitHub for migration stories, benchmark reproductions, and estate questions. Plain Australian English, evidence over adjectives: a performance claim without a run record is not a claim.

Contributing

The gate rule never bends: no change may mark a run proven except a byte-for-byte comparison against the legacy reference. Pull requests that weaken this - tolerance flags, partial comparisons, skip switches - are rejected. Everything else follows the normal course: tests, the sample pipeline, the evidence annex.

Governance

Bylazora is an independent project maintained by Bylazora (the company). The Open Mainframe Project is the target governance home as the community grows - the same home as Zowe, and the right neutral place for the byte-exact standard to live.
